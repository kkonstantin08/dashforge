# План реализации DashForge MVP

> Для реализации в текущем чате используй Superpowers Executing Plans. Все функциональные задачи проходят Superpowers TDD. Проверяй упрощения через Ponytail после GREEN. Перед завершением используй Verification Before Completion. При неожиданном сбое примени Systematic Debugging.

**Цель.** Опубликовать лёгкую локальную стартовую страницу с четырьмя виджетами, свободной сеткой, мягкими плитками и панелью настройки выбранной карточки.

**Архитектура.** Статическая Angular SPA, одна рабочая область, отдельная чистая логика геометрии, нативное IndexedDB с одной атомарной записью, Signals и ленивые компоненты виджетов.

**Стек.** Angular 22 и CDK, TypeScript 6.0 strict, Node.js 24.15.0+ в ветке 24, npm, Angular TestBed/Vitest, Playwright, ESLint, Prettier, GitHub Actions и GitHub Pages. На старте C подтвердить стабильные совместимые версии.

**Спецификации.** [Продукт, дизайн и критерии](../specs/product-and-design.md) · [Техническая спецификация и карта файлов](../specs/technical.md).

## Проверка черновика B

- Superpowers Brainstorming использован для проверки спецификаций вторым исполнителем. По итогам уточнены модальность инспектора, обновление ближайших событий и сохранность локальной модели при конфликте вкладок. Каждый сценарий связан с проверкой в C3, C4 или C8.
- Superpowers Writing Plans перевёл критерии приёмки в последовательные задачи и RED → GREEN → REFACTOR. План сверяется по ID критериев и контрактам между задачами.
- Ponytail оставил один экран, одну чистую логику сетки и одно хранилище. Узкая раскладка по умолчанию вычисляется, отдельная копия нужна только после правки. Локальные пиктограммы убирают зависимость от внешнего загрузчика favicon.

## Общие правила исполнения

- Начать этап C после согласования черновика B. Сохранить утверждённые цвета, типографику, геометрию, сценарии и любые отклонения в продуктовой спецификации.
- Для каждой функциональной задачи написать проверки из пункта RED, запустить тот же набор до и после реализации. RED должен зафиксировать отсутствующее поведение или неверный результат. GREEN требует прохождения набора. После REFACTOR повторить набор и общие проверки. Записать фактическую команду и результат каждой проверки в `docs/tdd/<task>.md` и сделать указанный логический коммит. Если рефакторинг ничего не улучшает, записать это в TDD-отчёте.
- `npm run test:unit -- --include 'src/app/**/file.spec.ts'` проверяет конкретный unit/TestBed-файл. `npm run test:e2e -- filename.spec.ts --project=chromium` проверяет конкретный браузерный сценарий. Полный запуск использует `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run test:unit`, `npm run test:e2e`, `npm run build`.
- Ревью в каждом шаге сверяет применимость к спецификации, проверки ошибок, сохранность данных и затронутые компоненты. В журнал TDD включать принятое упрощение или причину оставить дополнительную сложность. При исправлении дефекта сначала воспроизвести его тестом.
- Для автоматизации собственного сайта используем штатный Playwright. CloakBrowser оценивается по глобальной политике при изменении требований. Обычные сценарии на localhost обходятся без persistent profile и антибот-защиты.

## Риски для проверки

| Случай | Где проверяется |
|---|---|
| Новая вкладка сохранит раньше, старая начнёт запись со старой ревизией | C3, тест конфликта с двумя соединениями |
| Сохранение текста пересекается с переносом карточки и временным отказом IndexedDB | C3, очередь с контролируемыми транзакциями |
| Границы соприкасаются, но прямоугольники не пересекаются | C2, точные координаты и результат функции |
| Прокрутка, смена ширины или отмена касания происходят во время жеста | C4, мышь и сенсорный E2E |
| Наступление полуночи и переход месяца/года меняют дату и список событий | C5/C8, подставляемые время и часовой пояс |
