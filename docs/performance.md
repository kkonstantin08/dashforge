# Performance

Измерено 19 ноября 2026 года для production-кандидата DashForge 0.1.0. Метрики описывают один локальный стенд.

Apple M5, 10 ядер, 16 GiB RAM, Darwin 27.2.0 arm64, Node.js 24.22.3, Chromium 159.0.8154.6 headless. Viewport 1280 × 850, CPU и сеть без искусственного ограничения, HTTP-сервер на localhost с отключённым кешированием ресурсов. Для каждого профиля пять прогонов с новым изолированным контекстом. Reload выполнялся в том же контексте после первоначального открытия.

## Размер сборки

| Ресурсы | Raw, байт | gzip, байт |
|---|---:|---:|
| Initial JS, файлы в index.html | 235,292 | 75,988 |
| Initial CSS | 1,689 | 739 |
| JS до готовности рабочей области с четырьмя виджетами | 304,231 | 96,803 |

Initial JS до разделения был 278,037 байт raw. Ленивая загрузка панели снизила эту часть на 15.4%. При открытии панели появляется отдельный чанк в 4,893 байт raw. Стандартный экран загружает четыре виджета и общие зависимости. Суммарный JS до готовности сетки приведён в таблице. gzip посчитан локально на отдельных файлах с уровнем 9.

## Загрузка и восстановление

Готовность сетки измеряется от начала навигации до появления всех запланированных карточек с компонентами их виджетов. Чтение IndexedDB измеряется от создания readonly-транзакции до complete. CPU — счётчик TaskDuration рендерера, heap — JSHeapUsedSize на контрольной точке. Показатели в таблице — медианы, в скобках приведён диапазон времени готовности. Long tasks учитываются от 50 мс.

| Профиль | Сетка, мс | IndexedDB read, мс | CPU, мс | JS heap, MiB | Long tasks, сумма |
|---|---:|---:|---:|---:|---:|
| Первое открытие, пустое хранилище | 32.6 (32.0–33.6) | 0.1 | 32.3 | 3.64 | 0 |
| Сохранённый обычный макет · 4 виджета | 31.5 (27.1–32.2) | 1.0 | 31.6 | 4.11 | 0 |
| 5 виджетов | 31.5 (27.1–32.0) | 1.0 | 32.1 | 4.17 | 0 |
| 10 виджетов | 33.5 (33.3–33.7) | 1.0 | 33.9 | 4.64 | 0 |
| 20 виджетов | 36.7 (36.1–37.1) | 1.0 | 37.3 | 5.51 | 0 |
| Reload сохранённого макета | 16.1 (15.7–16.5) | 0.2 | 11.3 | 6.69 | 0 |

Число карточек в синтетических макетах увеличивалось при неизменном ассортименте из четырёх типов. Контент пустой, поэтому результат не характеризует большие заметки и массивы событий.

В макете из 20 виджетов автоматизация выполняла по 20 допустимых действий подряд. Время действия включает дискретные события указателя, отрисовку результата и ожидание Saved. Счётчик CPU показывает долю занятости одного главного потока рендерера за серию, без GPU и других процессов.

## Обновления компонентов и память

В development-сборке Angular profiler наблюдал один перенос в макете из 20 виджетов. При 20 событиях движения до отпускания Dashboard обновлялся 1 раз, перемещаемая карточка — 1 раз. После отпускания итоги составили 3 и 2 обновления соответственно. Остальные 19 WidgetCard и вложенные виджеты не обновлялись. Служебные embedded views Dashboard отслеживаются отдельно от компонентов карточек.

Для проверки удержания ресурсов использован принудительный GC в контрольных точках. После 40 жестов выполнены три серии по десять циклов добавления Clock, открытия инспектора и удаления карточки.

| Точка | JS heap, MiB | DOM-узлы |
|---|---:|---:|
| Перед жестами | 4.74 | 1576 |
| После жестов | 5.68 | 1600 |
| После 10 циклов | 6.45 | 1607 |
| После 20 циклов | 6.56 | 1607 |
| После 30 циклов | 6.64 | 1607 |

В повторных сериях число DOM-узлов стабилизировалось. Heap вырос и продолжал расти с меньшим шагом. Это короткая проверка, длительное удержание памяти требует отдельного профилирования на более длинной сессии. Производственное приложение не включает код замеров.

## Воспроизведение

Для production выполнить `npm run build`, запустить `npm run preview` в отдельном терминале, затем выполнить `npm run measure`. Скрипт использует чистый браузерный контекст и выводит исходные JSON-замеры.

Для Angular profiler остановить production preview, собрать `npx ng build --configuration development`, снова запустить `npm run preview` и выполнить `npm run measure -- --dev-checks`. Эта проверка использует счётчики Angular 22 только в development-сборке.

CPU замерен в Chromium. Физический телефон, сетевые условия публичного хостинга и более медленные устройства не вошли в baseline. [Сценарий замеров](../scripts/measure.mjs)
