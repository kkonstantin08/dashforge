# DashForge

Локальная стартовая страница с четырьмя настраиваемыми виджетами. При изменении поведения или интерфейса начни с [продуктовой спецификации](docs/specs/product-and-design.md). При работе с кодом используй [техническую спецификацию](docs/specs/technical.md) и соответствующий шаг [плана](docs/plans/mvp.md).

## Работа

- Применяй Superpowers для согласования дизайна, планирования, TDD, отладки, проверки и ревью. Применяй Ponytail, чтобы выбрать самое простое полное изменение. Сохраняй результат этих проверок рядом с задачей в документации.
- Согласуй изменение утверждённого дизайна до редактирования интерфейса. Границы новой функциональности определяют критерии приёмки.
- Для каждой функциональной правки пройди RED → GREEN → REFACTOR. Сначала упади по ожидаемой причине, затем сделай минимальную реализацию, проверь тест после рефакторинга и зафиксируй результаты в `docs/tdd/`.
- Каждый коммит решает одну задачу и имеет английский Conventional Commit типа `feat`, `fix`, `docs`, `style`, `refactor`, `test` или `chore`. `style` относится к форматированию исходников. Изменения внешнего вида оформляй как `feat` или `fix`.

## Код

- Используй Angular standalone, TypeScript strict, OnPush и zoneless, CSS Grid, Angular CDK и IndexedDB. Общие правила размещения и записи хранятся вне компонентов. Компонент отвечает за один виджет, панель или оболочку.
- Состояние и вычисления выражай через Signals и `computed`. RxJS применяй для потоков, где он нужен. Ограничивай время жизни подписок, таймеров и обработчиков. Реактивные формы используй для составных настроек.
- Во время drag и resize обновляй один контур. Валидируй и записывай результат по завершении. Сохраняй стабильные входные модели незатронутых виджетов. Проверяй результат оптимизации замерами.
- Поддерживай клавиатуру, видимый фокус, touch, экранное чтение подписей и ошибок. Проверяй границы данных при загрузке и до записи.

## Команды и завершение

После настройки проекта используй `npm ci`, `npm start`, `npm run lint`, `npm run format:check`, `npm run typecheck`, `npm run test:unit`, `npm run test:e2e` и `npm run build`. Цель команд и порядок проверок приведены в плане.

Перед завершением сверяй изменение со спецификацией и смежными сценариями. Для drag и resize приложи результат браузерного E2E. Фиксируй измерения в `docs/performance.md`, аудиты в `docs/audits/`, изменения продуктового контракта в `docs/specs/`. Ревью проверяет доступность, риск потери данных, зависимости, лишние перерисовки и покрытие критериев. Задача завершена после свежей проверки, фиксации результатов и логического коммита. Финальный независимый аудит выполняется по требованиям [плана выпуска](docs/plans/mvp.md#этап-e-публикация-и-аудит).
